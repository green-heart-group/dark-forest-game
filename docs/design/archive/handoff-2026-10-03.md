# 《三体·黑暗森林》3D 桌游模拟器 — 平台迁移交接文档

## 一、项目概述

游戏类型：3D 星域策略桌游模拟器，单人类玩家 vs 多个 AI 文明。
核心主题：黑暗森林法则——隐藏坐标、探知、威慑、打击、降维。
当前平台：Python + Tkinter + Matplotlib 3D。
目标：迁移到新平台（Web / Unity / Godot / 其他）。

---

## 二、核心数据结构

### 1. 星域

- 尺寸：10×10×10 = 1000 个整数坐标 `(x, y, z)`，x/y/z ∈ [0, 9]。
- 每个坐标的属性：
  - `star`：星系类型（无 / 单星 / 双星 / 三星）
  - `habitable`：是否适宜殖民（约 15%）
- 生成规则：
  - `P_HAS_STAR = 0.55`，有星系时随机选单/双/三星。
  - 有星系时 `P_HABITABLE = 0.15`。

## 三、核心机制

### 1. 行动点

- 单星：5，双星：4，三星：3。
- 每多一个殖民地 +1，上限 +2。
- 每回合重置。

### 2. 资源

- 能量：单星 +3，双星 +4，三星 +5；戴森球 +3。
- 矿石：单星 +2，双星 +2，三星 +2；采矿船 +2。
- 降维后产能减半。
- 星舰文明（无殖民地）：能量 +2，矿石 +1。

### 3. 建造（延迟 1 回合生效）

| 建造 | 消耗 | 效果 |
| --- | --- | --- |
| 射电望远镜 | 3E | 张角 +15° |
| 星际探测器 | 4M | 探知距离 +2 |
| 采矿船 | 4M | 产矿 +2 |
| 戴森球 | 12M | 产能 +3 |
| 预警系统 | 5E | 抵消一次打击 |
| 恒星广播器 | 6E | 允许广播，光粒前[?] |
| 引力波发射器 | 4E+4M | 允许广播 |
| 战舰 | 6E+6M | 生成战舰单位 |
| 殖民船 | 3E+3M | 生成殖民船 |
| 星舰 | 7E+7M | 生成星舰，可移动[?] |

### 4. 探知

- 消耗 2E，以母星为起点，沿斜率矢量发射圆锥。
- 圆锥张角 = `cone_angle`，长度 = `scout_range`。
- 覆盖范围内的敌方单位坐标加入 `known_coords`。

### 5. 打击

#### 战舰打击

- 消耗 3E，派出战舰沿矢量方向移动。
- 每回合移动 2 格（浮点步长，保证直线）。
- 遇敌停驻并造成 `strike_damage` 伤害。
- 出界消失。

#### 光粒打击

- 消耗 18E，需要恒星广播器。
- 以母星为起点，沿矢量方向瞬间命中第一个非己方文明。
- 若对方已降维：无效。
- 若对方有预警系统：抵消，损失一颗恒星及附属设施。
- 否则：直接摧毁。

#### 二向箔打击

- 消耗 20E，需要指定目标坐标。
- 以母星为起点，沿矢量方向飞向目标，每回合 1 格。
- 到达目标或遭遇文明时展开：
  - 目标 (x,y) 列被压平到 z_plane。
  - 该列所有文明：已降维者幸存并压到 z_plane，未降维者灭亡。
  - 黑域消失。
- 每回合扩散 1 格（frontier 算法）。

### 6. 自身降维

- 消耗 40E。
- 免疫光粒，仍可使用二向箔。
- 产能减半。

### 7. 黑域

- 消耗 28E，在探测范围内指定坐标生成 3×3×3 黑域。
- 捕获舰船和光粒，不捕获二向箔。
- 被二向箔波及则消失。
- 所有星系被黑域包围的文明默认灭亡。

### 8. 广播

- 需要恒星广播器或引力波发射器，消耗 4E。
- 广播某坐标后，若该坐标属于其他文明，有概率引来隐藏文明打击。
- 距离越近，触发概率越高。
- 隐藏文明只用光粒或二向箔。

### 9. 殖民

- 殖民船沿矢量移动，自动殖民最近的适宜星系。
- 殖民后 +1 HP。

## 四、降维视觉机制

### 数据结构

- `reduced_plane: Dict[(x,y), z_plane]`：记录每个被降维的 (x,y) 列及其平面高度。
- `dim2_frontier: Set[(x,y)]`：当前扩散边界。
- `dim2_centers`：展开中心列表。

### 视觉表现

- 白色空间网格：每个整数坐标一根竖线。
- 降维列：竖线分成两段，汇聚到 z_plane。
- 水平白线：经过降维列时，点被替换为 z_plane。
- 最终效果：整张 3D 星图逐渐压成 2D 平面。

### 性能优化

- 网格用 `Line3DCollection` 一次性绘制。
- 扩散用 frontier 算法，只处理边界列。
- 每回合只重绘一次，滑块变化实时刷新动态层。

## 五、AI 行为

### 阶段判断

- `explore`：无已知坐标时，探知 + 造探测器。
- `defend`：HP ≤ 2 时，造预警系统 + 戴森球 + 自身降维。
- `strike`：能量足够且有广播器时，光粒或二向箔打击。
- `expand`：造殖民船 / 战舰 / 探知 / 戴森球。

### 行动点

- 与人类一致，按星系类型和殖民地数量计算。

## 七、已知问题

1. 战舰和二向箔的浮点坐标：需要确保沿直线飞行，不阶梯化。
2. 降维扩散性能：列数多时重绘慢，已用 frontier + Line3DCollection 优化。
3. AI 偏弱：行动点已与人类一致，但策略仍简单。
4. 光粒太强：已削弱（需广播器 + 18E）。
5. 打包问题：`pyinstaller` 需用 `python -m PyInstaller` 并加 `--collect-data matplotlib`。

## 九、迁移建议

### 如果迁移到 Web

- 用 Three.js 做 3D 星图。
- 用 React / Vue 做 UI。
- 用 WebSocket 做联机。
- 降维效果用 shader 实现扭曲。

### 如果迁移到 Unity

- 用 GameObject 表示单位和坐标。
- 用 LineRenderer 画空间网格。
- 用 Shader Graph 做降维扭曲。
- 用 NavMesh 或自定义寻路做战舰移动。

### 如果迁移到 Godot

- 用 `ImmediateMesh` 画网格。
- 用 `ShaderMaterial` 做降维。
- 用 `Tween` 做动画。

### 核心逻辑可复用

- 数据结构（Civ、Unit、Game）可直接翻译。
- 矢量计算（cylinder_coords、cone_coords、ray_first_hit）是纯数学，可直接复用。
- 降维 frontier 算法可直接复用。
- AI 阶段判断可直接复用。
