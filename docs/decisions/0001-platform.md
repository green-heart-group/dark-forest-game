# 0001 开发平台：建议用 Godot 4

状态：**试用中**（2026-10-03 起用 Godot 4.7.2 搭原型），等 E7F6 确认。

## 背景

现在的版本用 Python + Tkinter + Matplotlib 做 3D 星图。它证明了玩法能跑起来，
但有明显的天花板：

- Matplotlib 是画图表的工具，不是游戏引擎，旋转、动画、特效都很吃力。
- 交接文档里的大部分待办（动画、音效、多人对战、美术）在这套技术上很难做好。

目标版本的规则改动很多（见 [game-design.md](../design/game-design.md)）。
如果先在 Python 版里实现一遍、换平台后再实现一遍，等于做两次。

## 做法：先定平台，再做原型

这是游戏开发的通常做法：

1. **定平台**：选好引擎，之后所有新规则只在新平台上做。
2. **做原型**：用最简单的方块和线条（不做美术），只实现核心循环：
   探测、选发射源、打击、打中反馈、恒星减一。目的是尽快验证「好不好玩」。
3. **边玩边调**：原型能玩以后，再加防守手段、调数值、改 AI。
4. **最后才做美术和音效**：玩法定型后再投入，避免返工。

另外两条习惯：

- **规则和画面分开写**：规则代码（谁打中谁、恒星怎么算）不依赖画面，
  这样能单独测试，以后换画面也不用重写规则。
- **旧 Python 版冻结**：不再加新功能，作为「旧规则说明书」留着对照。
  后来归档到单独的分支，见 [0002](0002-archive-python.md)。
  已知的两个二向箔 bug 不修，记下来，新版本避开即可。

## 选项比较

| | Godot 4 | Web（Three.js） | Unity |
| --- | --- | --- | --- |
| 编程语言 | GDScript，写法接近 Python | JavaScript / TypeScript | C# |
| 费用和授权 | 免费，开源（MIT 许可证） | 免费 | 有收费条款，曾经变动过 |
| 3D 能力 | 够用，适合这种网格和线条 | 够用，但要自己搭很多东西 | 最强 |
| 发布 | Windows、Mac、网页、手机 | 网页，发链接就能玩 | 全平台 |
| 上手成本 | 低 | 中，需要另选界面框架 | 高，引擎很重 |

## 建议

**选 Godot 4。** 理由：

- 回合制、网格、线条为主，不需要 Unity 那样重的引擎。
- GDScript 和 Python 很像，现有代码里的规则可以直接对照着翻译。
- 免费开源，没有授权风险；也能导出网页版，方便发给别人试玩。

如果「打开网页就能玩」和「多人在线」是第一优先，可以改选 Web（Three.js）。
