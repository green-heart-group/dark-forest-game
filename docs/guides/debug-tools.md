# 开发者调试模式

给开发者和试玩的人用的调试面板：换成任意文明的视角、看 AI 每回合做了什么和为什么、
一回合一回合播放对局、随时改数值、存下对局记录发给别人重现。
这一页只讲面板怎么用；面板的代码在哪个文件见 [代码结构](code.md)。

## 怎么打开

- 从编辑器或 `godot --path game` 运行时，按 **F12** 打开或收起面板。上次开着，下次启动还开着。
- 面板是一个单独的窗口，不挡星图：可以拖到游戏窗口旁边或第二块屏幕上，也可以拉大拉小，下次打开还在原处。
  点窗口的关闭按钮等于按 F12 收起。焦点在面板窗口上时，F12、空格、← → 这些快捷键照样能用
  （正在输入框里打字时除外）。
- 导出的普通版平时没有这个面板，要在命令行加参数才有：

```bash
# 打开调试面板
godot --path game -- debug

# 开一局全由 AI 打的观战局（同一个种子每次都一样）
godot --path game -- watch seed=123

# 打开一份对局记录，从开局开始回放
godot --path game -- replay=C:/路径/xxx.replay
```

导出的 exe 也一样，参数写在 `--` 后面，例如 `dark-forest.exe -- debug`。
发布时还会多放一个开发者版 `dark-forest-windows-dev.zip`，里面的 `dark-forest-dev.exe` 双击就打开调试面板，不用加参数。

网页版没有命令行，参数写在网址的 `?` 后面，用 `&` 隔开：

- <https://green-heart-group.github.io/dark-forest-game/dev/>：开发者入口，会转到 `?debug`，打开调试面板，之后按 F12 收起或打开。
  `dev/?watch&seed=123` 开观战局，`?seed=123` 重玩同一张星图（不打开面板也能用）。
- 面板画在游戏网页里面，可以拖动标题栏挪开。浏览器自己也用 F12 打开开发者工具；
  要是按 F12 时浏览器的工具也弹出来，点面板右上角的 ✕ 收起面板。
- 网页版碰不到电脑上的文件夹，游戏存的文件（对局记录、数值方案）放在浏览器里。所以这几个按钮换了做法：
  「保存记录」同时下载一份；「打开记录」「导入文件…」让你从电脑上选文件；
  「打开文件夹」换成「下载 last.replay」和「下载」（选中的数值方案）。
- 「写回 balance.cfg」只在编辑器里运行时才有，exe 和网页版都没有。

快捷键（面板开着、没有在输入框里打字时）：空格 播放/暂停，← → 后退/前进一回合，Home/End 跳到开头/结尾，
1～9 换成第几个文明的视角。

## 面板里有什么

最上面是**播放**：⏮ 回到开局、◀ 后退、▶ 播放、▶| 前进、⏭ 跳到最后，可以选播放速度，拖进度条跳到任意回合。
自己玩的局，播放到轮到玩家操作时会停下；按 ▶| 等于直接结束这一回合。

下面一行是**视角**：选一个文明，星图、资源栏、科技和建造页都换成它看到的样子（它不知道的东西不会画出来）。
「由 AI 控制」去掉勾，就由你来操作这个文明；勾上就交给 AI。所以既可以看 AI 怎么打，也可以替 AI 打几步，
或者让 AI 替你打。「上帝视角」把所有文明的星系和舰船都画出来，标出各家母星系。

**你灭亡以后**：平时对局到这里就结束了。调试时有两种办法接着看其余文明打到分出胜负：

- 事先勾上「你灭亡后对局不结束，其余文明接着打」；
- 已经结束了，按面板上出现的「💀 你已灭亡：继续往下看」。它会重算你灭亡的那一回合，这次不结束对局。

之后可以一直播放，也可以换成任何还活着的文明的视角。最后的胜负写赢家的名字。

四页：

- **📋 一览**：每个文明的星系、能量、矿石、科技、单位、知道几个敌方星系、被打中几次。点名字换视角。
  下面是看着的这个文明最近 4 回合做了什么，💭 开头的是 AI 写下的想法（比如「知道 2 个敌方星系，打最近的」
  「想发二向箔，要攒到 60E」），🙋 开头的是玩家的操作。
- **🔧 数值**：`balance.cfg` 里的所有数值，名字下面是那个文件里的注释。改了从这一回合起生效，↺ 恢复成 `balance.cfg` 里的值。
  可以按名字或说明筛选，或者只看改过的。数组写成 `[6, 3, 1]`，按回车生效。上面是「方案」，见下一节。
- **🧬 文明**：直接改看着的这个文明的能量、矿石、行动点、望远镜等级、几级科技开没开放等，
  勾选科技就直接得到。上面有「+100 能量」「全部科技」等快捷按钮。
- **💾 记录**：保存、打开对局记录，打开存记录的文件夹；用指定的种子新开一局（自己玩或观战）。

改过数值的对局，状态栏会写「🛠 改过数值」。以后做成绩、排行时，这样的对局不算（`GameState.dev_used`）。

## 数值方案

一组和 `balance.cfg` 不一样的数值，可以存成一个「方案」文件，方便切换、发给别人、拿去跑平衡模拟。
方案是普通文本（`.cfg`），只记改过的数值，可以直接打开看、直接改：

```ini
[info]
note="能量多一点"

[values]
START_ENERGY=30
STAR_WEIGHTS=[6, 3, 1]
```

方案放在两个地方：

- **📁 共享的**：`game/balance_presets/`，提交进 git，大家都能用。只有用编辑器版运行时能存到这里。
- **👤 自己的**：`user://balance_presets/`（Windows 上在 `%APPDATA%\Godot\app_userdata\dark-forest\balance_presets\`），不进 git。

「🔧 数值」页最上面：

- 选一个方案按 **用上**：数值换成这个方案的，方案里没写的用 `balance.cfg` 里的。从这一回合起生效，也记进对局记录。
- **恢复默认**：所有数值换回 `balance.cfg` 里的。
- **新开一局时用选中的方案**：勾上后，打开游戏和新开一局都先换成这个方案。这样开局的数值记在对局记录的开局数值里，不算「改过数值」。
- **存成方案**：写个名字，把现在和 `balance.cfg` 不一样的数值存下来（同名的覆盖）。勾「共享（进 git）」存到共享目录。
- **导入文件…**：选别人发来的 `.cfg`，复制到自己的方案里。导出就是「打开文件夹」把文件发给别人。
  方案里有 `balance.cfg` 里已经没有的名字、或者类型对不上的值，会跳过并提示。
- **写回 balance.cfg**：只在用编辑器版运行时有。把现在的数值写进 `game/balance.cfg`，只换值，名字和注释都留着。
  写完跑 `uv run game/tools/update_docs.py`，把 [原型现在的规则](../design/current-rules.md) 里的数字改成新的，
  看看这些数值旁边的注释和规则文档里的文字还对不对，再提交。

平衡模拟也能用方案，后面写的数值会盖过方案里的：

```bash
godot_console --headless --path game --script res://tools/simulate.gd -- PRESET=方案名 RUNS=100
```

## 对局记录和回放

每结束一回合，这一局的记录会自动存到 `user://replays/last.replay`
（Windows 上在 `%APPDATA%\Godot\app_userdata\dark-forest\replays\`，面板里「打开文件夹」可以直接打开）。
遇到问题时，把这个文件发给别人，对方用 `-- replay=文件` 打开，就能看到一模一样的对局。

### 记录里存了什么

不存每回合的整个局面，只存能重新算出局面的东西（游戏里常说的「记输入，不记状态」）：

- 开局的种子、AI 个数、是不是观战局；
- 开局时 `balance.cfg` 的全部数值；
- 玩家做过的每一次操作（升级、建造、派出、发射……），以及调试时改过的数值、换过谁来控制；
- 每结束一回合后局面的校验值（把主要数据算成一个数）。

AI 的操作不用存：规则里所有随机数都来自 `GameState.rng`，同样的种子、同样的玩家操作，AI 会做出同样的决定。
回放时从开局按记录重算，每回合对一下校验值。对不上（比如记录以后改了规则或数值），面板会用红字写出是第几回合开始不一样；
走偏的对局如果比记录先结束，回放就停在那里，变回普通的对局。
打开记录时，如果记录里的数值和现在的 `balance.cfg` 不一样，会先换成记录时的数值（只在这次运行里有效）。

往回退、拖进度条时，面板先找「局面缓存」：调试面板在内存里存的一些回合的完整局面
（最近走过的 10 个回合，加上每 10 回合一份；自动播放时只存每 10 回合那份，免得播放变慢）。
要去的回合在缓存里就直接取出来；不在就从不晚于它的最近一份按记录补算，补算路上也存。
第 150 回合退一回合，原来从开局重算要 4.8 秒左右，现在约 0.07 秒；缓存里没有、要补算几回合时不到 1 秒。
补算超过 0.1 秒时分段算，面板上显示算到第几回合，窗口照常响应；按 Esc 或「取消」停下，留在原来的回合。算的时候不能操作。

缓存里的局面打包成压缩的字节存（`game/rules/state_copy.gd`），一份 150 回合的局面一百多 KB，打包、取出各要几十毫秒
（2026-10-08 在开发机上测，150 回合的观战局缓存 25 份共约 2.5 MB）。取出来的是新的一份，怎么改都不影响缓存。
每份都记着走到那里的对局记录，取的时候核对开局和之前每一次玩家操作都和现在的记录一样，
所以换了记录、从中间另开一条路时不会取到另一条历史的局面；新开一局、打开记录时整个清空，另开一条路时丢掉分叉点以后的。

在回放中间按「从这里接着玩」，就丢掉之后的记录，从这一回合开始自己操作。

### 写规则代码时要注意

为了让回放算出一样的结果，规则代码要守这几条（规则测试 `game/tests/rules/test_replay.gd` 会检查）：

- 随机数只用 `GameState.rng`，不要用 `randf()`、`randi()` 这些全局随机数。
- 玩家能改变局面的操作，都要写成 `GameState` 里的函数，成功时调用 `_record(civ, 函数名, 参数)` 记下来。
  参数要记**调用时传进来的原样**（函数里改过的不算），回放时用同样的参数再调用一次。
- 操作失败（钱不够、目标不对）时不记录，所以也不能用掉随机数：先检查完能不能做，再抽随机数。
- 画面代码不能直接改规则数据，只能调用这些函数。调试用的改动也一样，走 `dev_set`、`dev_balance`、`dev_tech`。
- AI 想解释自己为什么这样做，用 `s.ai_note(ai, "……")`；只给调试面板看，不进回放。
- 新加的属性如果会影响对局，最好也加进 `GameState.checksum()`，这样走偏了能更早发现。
- `GameState`、`Civ` 新加的属性里如果要放文明、舰船、箔这样的对象，要加进 `StateCopy.LINKS`，不然局面缓存会把它当普通数据存而丢掉。
  `test_state_copy_is_independent` 会扫一遍局面，发现漏了就失败。

## 以后

- **多人对战**：画面已经是按「看哪个文明」来画的（`main.gd` 的 `viewed()`），不是写死的「玩家」。
  联网以后，每个玩家只能看自己的文明；看别人的视角、上帝视角、改数值都只在调试模式里有。
  对局记录里本来就记了每个操作是哪个文明做的，多个玩家也能用同一种格式。
- 存档、读档可以直接用对局记录来做（读档 = 打开记录，跳到最后）。

这几项什么时候做，见 [路线图](../roadmap.md)。
