# 连续结算改成事件队列

提议：RainZL。状态：**讨论中**（2026-10-11，第 0～4 阶段已做，结果见文末）。

## 想解决什么

结束一回合时，规则把这一年切成一段段小步来算（`WorldTime.advance`）。每切一刀，不管这一刀是因为什么，
都要把整个世界重做一遍：所有文明的收支计划、所有船的运动和边界、所有可能的碰撞、所有工程、所有视野。

[结算步长改成 1 年](one-year-step.md) 以后，固定的刻度已经没有了，每一刀都对应一件真的发生的事。
所以刀数省不下来，要省的是**每一刀的花费**：一件事只动和它有关的东西。

量到的数（种子 632646，第 251～300 回合，单进程）：

| | 数 |
| --- | --- |
| 每回合用时 | 约 0.36 秒，其中连续结算约 0.27 秒，AI 约 0.07 秒，校验值约 0.014 秒 |
| 每回合刀数 | 约 8 刀（第 300 回合前后 14 刀） |
| 每一刀的花费 | 约 33 毫秒 |

每一刀里的时间：

| 每一刀做的事 | 占连续结算 | 这一刀里真正需要做的 |
| --- | --- | --- |
| 看一遍所有视野（`Signals.sample`） | 42% | 只看这件事改变了的东西，和刚好进入视野的东西 |
| 查一遍所有工程有没有完工（`_finish_pending`） | 25% | 只查到了完工时刻的那一项，和宿主或条件变了的 |
| 所有船的边界、碰撞、相交（`events_in`、`next_boundary` 等） | 12% | 只重算运动变了的船 |
| 收支积分、移动、伤害 | 9% | 移动和积分要做（很便宜），伤害只在有命中时 |
| 每个文明的收支计划（`Economy.plan`） | 8% | 只在这个文明的星系、舰船、设施、科技、库存方案变了时 |

再细分一层（同样 50 回合，开始动手前量的）：

- 看视野每一刀平均有 65 个观察者、409 对「观察者和星系」、1737 对「观察者和单位」，要拍 205 个星系快照。
  最贵的是**动的观察者**：每一刀都把视野里所有星系重新判断一遍「这一小步里有没有扫进视野」，而它的运动多数时候没变。
- 查完工那 25% 里，真正查完工的只是一小部分；大部分是顺带**收消息**（50 回合 3.4 秒）。收消息慢不在查找，
  而在收下以后的处理：每收一条己方舰船或据点回报，都把「战况查询」的收件者整个重算一遍（每条 0.3～0.4 毫秒），
  每收一条单位观测，都在整张观测表里逐条找同一单位（每条约 0.5 毫秒）。

刀从哪里来（同样 50 回合，共 410 刀）：命令送达 103、工程完工 69、观测送到带武器的船或星舰 39、船加速到最高速度 36、
降维前沿扫到有东西的格子 35、一年结束 35、船进出己方星系视野 28、船进入规则不同的格子 26、其余 59。

目标：后期每一刀的花费降到 5 毫秒以下，第 251～300 回合每回合 0.1 秒以下。

## 新的做法

### 总体

- **一张按时间排好的事件表**（最小堆）。每一项是「某个时刻、某样东西会发生什么」，按（时刻，同刻先后，序号）排。
  每次取最早的一件（同一时刻的一起取），把时钟推到那一刻，处理它们。
- **状态仍在每个事件时刻统一推到当时**：船按运动公式挪到那一刻，各文明按当前收支速率积分到那一刻。
  这两件事很便宜（每刀约 1 毫秒），这样别的规则代码读到的 `ship.pos`、`civ.energy` 都是当时的值，不用全部改写成「按需推算」。
  这是和[一年步长提议](one-year-step.md#以后再说各管各的事件队列)里设想的「各样东西随时间的式子」不同的地方：
  只把**预测**（下一件事什么时候发生）和**查找**（谁看到了谁、哪项工程完工）改成事件，状态推进保持统一。
- **预测只在需要时重算**。每条预测记下它依赖什么（某艘船、某个文明、某个格子，或者整个环境）。
  处理一件事时，把它改变了的东西**标记为变了**；处理完这一批，只重算依赖这些东西的预测。
  过时的预测不从堆里删，每样东西带一个版本号，取出来时版本对不上就丢掉。

### 同一时刻的先后

现在一刀里的处理顺序有规则含义（比如同刻的伤害一起结算，再看谁灭亡）。新的做法保持这个顺序：
同一时刻取出的事件，按现在一刀里的阶段顺序处理：

1. 环境变化（黑域、死线、降维前沿、换图）
2. 积分和移动到这一刻
3. 碰撞和命中、压制和光粒、载荷和前沿、广播波前
4. 工程完工
5. 收消息
6. 看视野（只看变了的）
7. 修理、清理、判胜负

同一阶段里按序号处理，序号在事件进表时按确定的顺序给出，所以同样的种子算出来一样。

### 每种事件：从哪里来、什么时候要重算

| 事件 | 预测依赖 | 什么时候重算预测 |
| --- | --- | --- |
| 一年结束 | 无 | 每回合开始放一个 |
| 命令和其他必须准时的消息到达 | 消息本身 | 发出、重算路线时（现在已经是这样，`Signals._indexed`） |
| 观测送到带武器的船或星舰 | 消息本身 | 同上 |
| 工程完工 | 这个文明的收支计划、工程 | 这个文明变了、这项工程变了 |
| 船加速到最高速度、到达、暂停结束 | 这艘船的运动 | 这艘船变了 |
| 船进入规则不同的格子、进出己方星系视野、曲率越过上限、黑域里每 0.2 年一段 | 这艘船的运动、环境 | 这艘船变了，或环境变了 |
| 弹丸、载荷的射程和边界 | 它自己、环境 | 它变了，或环境变了 |
| 碰撞和命中（弹丸、水滴、自杀撞击） | 两边的运动 | 任一边变了 |
| 压制进度、压制范围进出 | 战舰的运动、殖民地 | 战舰变了，或有殖民地增减 |
| 殖民船等到达星系、光粒撞上恒星 | 船的运动、星系 | 船变了，或星系变了 |
| 广播波前扫到移动的船 | 波前、船的运动 | 船变了，或环境变了 |
| 黑域、死线、降维前沿、空间事件的变化 | 环境 | 环境变了 |
| 目标进入视野（见下一节） | 观察者和目标的运动 | 任一边变了 |

「环境变了」包括：黑域和死线出现、长大、到期，格子降维，换图，地图阶段变化。环境一变就重算所有依赖环境的预测，
这和现在每一刀都重算一样贵，但环境变化本身很少。

### 视野

现在每一刀都看一遍所有视野。改成：

- **每回合开头和结尾各看一遍全部**（和现在开头的那一遍相同）。心跳（内容不变时每年重发一次）由这两遍负责，
  最晚隔「1 年加一个子步」，和[推算的过时时间](../../game/rules/combat.gd)一致。
- **中间只看变了的**：一件事改变了某艘船的运动、某个星系的样子、某个文明的观察者（新建、摧毁、休眠），
  就只对这些东西重看一遍：变了的目标，被所有能看到它的观察者看；变了的观察者，看它视野里的一切。
- **预测进入视野**：观察者和目标在两次变化之间都按二次式运动，进入视野的时刻可以提前算出来
  （现在的 `_first_seen` 已经会算，只是用在过去的一步上）。把它放进事件表，到时按那一刻发出观测。
  移动的观察者扫过的星系、航迹端点、空间前沿也一样。
- 预警系统、殖民地的现场报告、己方舰船的状态报告同样处理：每回合首尾全看，中间只看变了的。

### 收支和工程

- 每个文明的收支计划按这个文明的版本号缓存：星系、舰船、设施、科技、停用和优先级、压制目标变了，版本号加 1。
  库存只在净收入为负时影响计划，而同样的速率下，「库存够撑到年底」随时间不会变成不够，所以库存变化不用重算。
- 每项工程按当前速率算出完工时刻，放进事件表；这个文明的计划变了就重算。
- `_finish_pending` 只处理到了完工时刻的工程，以及宿主或条件可能变了的那几项（宿主被毁、星系易手、休眠）。

## 防止漏掉

最大的风险是：某件事改变了一样东西，却忘了标记它变了，于是该发生的事没发生。这种错不报错，只是悄悄算错。

所以加一个**核对模式**（只在测试和调试时打开）：每取出一批事件之前，用现在的办法把所有东西重新问一遍，
得出「下一件事的时刻」，和事件表给出的比；处理完以后，用现在的 `Signals.sample` 全看一遍，看有没有该发却没发的观测。
对不上就报错，并写出是哪一种事件、哪样东西。新加一个规则测试，在核对模式下打一整局长局。

核对模式一直留在代码里，以后加新规则时也靠它发现漏掉的标记。

## 分阶段做

每一阶段做完：全部测试 0 个失败，核对模式下的长局没有报错，量一次速度，在这里记下数字。

0. **收消息的两处**（细量后加的）：战况查询的收件者直接从回报里取编号和位置，不再为每艘船重建一份状态。结果不变。
1. **事件表和核对模式**：主循环里每一个「下一件事什么时候发生」都带上原因放进事件表，取最早的一件。
   每一刀仍按现在的办法把所有预测重算一遍。结果应该和现在完全一样（校验值不变）。顺带记下每一刀是因为什么切的。
2. **视野**（细量后提前）：每回合开头全看一遍；中间每一刀只看变了的东西，加上预测好的进入视野。
   「变了」不靠各处手动标记，而是每一刀比较每样东西的样子：运动和按上次运动推算的对不上、种类损伤等变了、
   所在的格子变了、星系的快照变了，就算变了。这样漏标的风险最小。
3. **运动和碰撞的预测按需重算**：船、弹丸、载荷的各种时刻，碰撞和相交，只在它们变了或环境变了时重算。
4. **收支计划和工程完工**按文明版本号缓存和预测。
5. **清理**：删掉不再需要的旧代码，更新文档。

第 0、1、3、4 阶段应该不改变结果或只改变很少；第 2 阶段会改变观测发出的时刻（只会更准或稍晚，不会更早），校验值会变。

### 视野的细节

- 每回合开头（`WorldTime.advance` 开始时）照现在的办法全看一遍，心跳（内容不变时每年重发）只在这时补发。
  上次发出在回合中间的，最晚隔将近 2 年重发，仍在[推算的过时时间](../../game/rules/combat.gd)（1 年加 1 个最长子步）以内。
- 每一刀结束时，先算出每个单位、每个观察者、每个看得到的星系的「样子」，和上次记下的比：
  - 变了的单位和观察者：按现在的办法（这一小步扫过、现在在不在视野里）和所有相关的对象重看一遍，再预测它从现在到这回合结束什么时候进入哪些视野。
  - 变了的星系：看得到它的观察者重看它。
  - 都没变的：只处理预测好的、在这一小步里进入视野的那几对，按进入那一刻的位置和速度发出（和现在一样）。
- 一直在视野里、运动没变的，按航位推算本来就不用重发，所以只看「进入」就够了。

## 做下来的结果（2026-10-11）

第 0～4 阶段都做了。第 3、4 阶段没有给每条预测记依赖和版本号，而是用了更简单、也更不容易漏的两种办法：
先用便宜的方框和距离**粗筛**，排除不可能的，剩下的才精确算；按内容算一个**签名**（把一组数据压成一个数），签名和上次一样就用上次的结果。
第 2 阶段改了观测发出的时刻，回放版本升到 8；之后的改动只让算得更快，种子 632646 第 300 回合的校验值一直是 191759045。

做了什么：

- **视野**（第 2 阶段之后又加的）：
  - 每个单位到这回合结束可能扫过的方框放进网格；运动变了的观察者只和方框碰得到自己视野的单位比，不再和所有单位逐个比。
  - 所有星系的事实（谁的殖民地、设施、光速、各格的维度等）算一个签名，没变就不逐个拍星系快照。
  - 每个文明的据点情况算一个签名，没变就只补发到了心跳时间的据点报告。
- **运动和碰撞**（第 3 阶段）：「各处光速是否一样」按环境的版本号记住；压制和碰撞先按方框和最近距离粗筛；不动的战舰不查压制。
- **收支和工程**（第 4 阶段）：收支计划按「工程清单、停掉的包、维护顺序」的签名记住；
  另记一份还没完结的工程回报，不用每次扫全部历史；建造检查先做便宜的判断。
- **查找**：查已报告的舰船时可以只要某几种；记住「查过、不是船」的编号；找控制点找到第一个就停。

速度（种子 632646，300 回合；改前、改后两局在同一台机器上同时跑，抵消机器忙闲的影响，跑了四次）：

| | 改前 | 改后 |
| --- | --- | --- |
| 第 1～300 回合合计 | 55.8～63.7 秒 | 41.2～46.1 秒 |
| 第 251～300 回合合计 | 21.3～27.9 秒 | 15.8～17.7 秒 |

平衡模拟 50 局（每局最多 300 回合，8 个进程）：改前 402.8 秒，第 2 阶段后 322.6 秒，全部做完 217.6 秒；
后两次所有对局的校验值一样（4184568704），各项统计也一样。和改前比（第 2 阶段改了观测时刻，对局不同）：
能升 II 级的文明 156 和 152，首个文明灭亡 44 局和 46 局，分出胜负 41 局和 43 局，第 150 回合平均存活 4.04 和 3.98，
淘汰原因空间前沿 161、光粒 11 和空间前沿 168、光粒 11，都在波动范围内。

改后单独跑（核对模式）：300 回合 31.2 秒，第 251～300 回合 12.9 秒，即每回合约 0.26 秒，每一刀约 27 毫秒。
**目标（每一刀 5 毫秒、每回合 0.1 秒）没有达到。**

第 251～300 回合的时间还花在这些地方（50 回合合计，带临时计时，绝对数偏高）：

| 做的事 | 用时 |
| --- | --- |
| 看视野（`Signals.sample`） | 4.5 秒，其中发出星系观测 1.1 秒（约 2.2 万条） |
| 收消息 | 2.3 秒，其中星系观测 0.7 秒 |
| AI 做决定 | 1.8 秒 |
| 边界和相交 | 1.4 秒 |
| 维护和就绪 | 1.2 秒 |
| 校验值 | 0.8 秒 |
| 收支积分和伤害 | 0.6 秒 |

到这里没有哪一项超过三分之一，剩下的大多是真要做的事：每条观测都要拼消息、瞄准在动的收件者、收下后记进情报。
星系观测几乎都是一条一条发的：每个星系离观察者的距离不同，光到达的时刻不同，合不到一起。
再要大幅提速，得改规则本身，比如内容没变的星系心跳发得少一些，这会改变情报到达的方式，要另外讨论决定。

## 不变的底线

- 情报只许晚到、不许早到；AI 和玩家拿到的近似一样；同样的种子加同样的操作是同样的对局。
- 伤害、到达、完工、灭亡按准确时刻排先后；同一时刻全灭才平局。
- 对外的函数保持不变：`WorldTime.advance(s, 年数)`、`GameState.end_turn()`，测试和画面不用改调用方式。
- 对局结果变了就升 `Replay.VERSION`。

## 验收

- 全部测试 0 个失败；核对模式下的长局测试没有报错。
- 平衡模拟 50 局和改之前比，各项统计在波动范围内。
- 速度：种子 632646 第 251～300 回合每回合用时和每一刀的花费；平衡模拟 50 局的用时。写进开发日志。
- 达不到目标或带来的复杂度不值得，就只保留有用的阶段，或者整个放弃；分支是实验分支，不一定合并。
